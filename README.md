# יציאות מחלקה 1

אפליקציית מעקב אחר יציאות חיילים למחלקה 1. מפקד יכול להזין בקשות יציאה
לכל חייל (יום בודד או טווח), לאשר / לא לאשר / למחוק אותן, ולצפות בכל המידע
בתצוגת לוח שנה. הנתונים נשמרים בבסיס נתונים (SQLite) ולכן נשמרים בין הכניסות.

הממשק בעברית מלאה, RTL, ומותאם קודם כל לנייד.

כשהאפליקציה רצה על שרת מקוון אחד, **כל המפקדים שנכנסים לאותה כתובת חולקים
את אותם נתונים בזמן אמת** — כלומר יש סנכרון מלא בין המכשירים. להעלאה לאירוח
מקוון ראה את [DEPLOY.md](DEPLOY.md).

## כניסת מפקדים (סיסמה)

הכניסה מוגנת בסיסמה משותפת אחת. מגדירים אותה דרך משתני הסביבה:

- `APP_PASSWORD` — הסיסמה שהמפקדים יזינו במסך הכניסה
  (ברירת מחדל להרצה מקומית: `mahlaka1`).
- `SESSION_SECRET` — מפתח סודי אקראי לחתימת עוגיית ההתחברות
  (**חובה** להגדיר ערך אקראי בפרודקשן).

ההתחברות נשמרת בעוגייה מאובטחת (HttpOnly) למשך 30 יום.

## יכולות

- **לוח שנה** — תצוגה חודשית. לחיצה על יום מציגה כמה חיילים בחוץ וכמה נשארים,
  ואת רשימת הבקשות לאותו יום. ימי היציאה המחלקתית מסומנים בירוק בהיר וכל
  המחלקה נחשבת "בחוץ" בהם.
- **בקשות** — הוספת בקשת יציאה (יום בודד או טווח מתאריך–עד תאריך). כל בקשה
  חדשה נפתחת כ**"בטיפול" (אדום)**. ניתן לאשר (**ירוק**), לא לאשר (**שחור**,
  מופיע תחת "בקשות שלא אושרו") או למחוק. אישור/דחייה/מחיקה חלים על כל הטווח.
- **רשימת שמות** — כל החיילים ממוינים לפי שם המשפחה, עם מונה של סך ימי
  היציאה האישית שאושרו לכל חייל.

## סימון צבעים

| צבע  | משמעות              |
|------|---------------------|
| אדום | בקשה בטיפול          |
| ירוק | יציאה מאושרת         |
| שחור | בקשה שלא אושרה       |
| ירוק בהיר | יום יציאה מחלקתית |

## הרצה

דרוש Node.js גרסה 18 ומעלה.

```bash
npm install
APP_PASSWORD='בחר-סיסמה' SESSION_SECRET='מחרוזת-אקראית' npm start
```

ואז נכנסים לכתובת http://localhost:3000 ומתחברים עם הסיסמה שהגדרת.
(ללא הגדרת משתנים, הסיסמה לברירת מחדל היא `mahlaka1` — להרצה מקומית בלבד.)

אפשר להעתיק את `.env.example` ולהיעזר בו.

לשינוי הפורט: `PORT=8080 npm start`.
לשינוי מיקום בסיס הנתונים: `DB_PATH=/path/to/data.db npm start`.

## העלאה לאירוח מקוון

ראה מדריך מפורט שלב־שלב ב-[DEPLOY.md](DEPLOY.md) (מותאם ל-Fly.io).

## מבנה

- `server.js` — שרת Express ונקודות ה-API.
- `db.js` — הגדרת בסיס הנתונים (SQLite) וזריעת נתוני ההתחלה (חיילים + לוח
  יציאות מחלקתיות).
- `public/` — הממשק (HTML / CSS / JS ללא תלות בספריות צד-שלישי).

בסיס הנתונים נשמר בקובץ `data.db` (נוצר אוטומטית בהרצה הראשונה, ואינו נכלל
ב-git).

## נקודות API עיקריות

כל נקודות ה-API (למעט ההתחברות) מוגנות ודורשות עוגיית התחברות תקפה.

| שיטה   | נתיב                    | תיאור                                |
|--------|-------------------------|--------------------------------------|
| POST   | `/api/login`            | התחברות (`password`) — מחזיר עוגייה  |
| POST   | `/api/logout`           | התנתקות                              |
| GET    | `/api/session`          | בדיקת מצב התחברות                    |
| GET    | `/api/soldiers`         | רשימת חיילים ממוינת + ימי יציאה מאושרים |
| GET    | `/api/department-exits` | לוח היציאות המחלקתיות                 |
| GET    | `/api/requests`         | כל הבקשות (סינון `?status=` / `?date=`) |
| POST   | `/api/requests`         | יצירת בקשה (`soldier_id`, `start_date`, `end_date`) |
| PATCH  | `/api/requests/:id`     | עדכון סטטוס (`approved`/`rejected`/`pending`) |
| DELETE | `/api/requests/:id`     | מחיקת בקשה                            |
| GET    | `/api/day/:date`        | סיכום יום (בחוץ / נשארים / בקשות)     |
| GET    | `/api/calendar?month=`  | נתוני חודש ללוח השנה                  |
